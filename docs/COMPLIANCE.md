# 合规基线 · 网络游戏账号交易版权监测系统

本文件是 V1.0 的合规约束清单。系统定位是**权利监测与处置辅助**，不是爬虫武器，也不提供任何账号交易能力。

## 1. 采集范围

| 项 | 规定 |
| --- | --- |
| 目标数据 | 渠道上**公开可见**的商品标题、描述、标价、卖家公开标识、页面链接 |
| 禁止采集 | 买家/卖家个人信息（手机号、身份证、住址）、账号凭据、聊天记录、支付信息 |
| 禁止手段 | 绕过登录态、破解验证码、伪造请求头伪装普通用户、高频压测 |
| 数据落地 | 只保留取证所需的文本快照，卖家标识做脱敏占位；数据库文件本地存储 |

## 2. 渠道关系

- 默认 1.2 秒/请求、单次巡检最多 3 页，属于低频礼貌抓取。
- 正式使用前，应优先与渠道签订数据合作或走官方开放接口；本框架的 `adapter.mjs` 已预留接口切换位。
- 渠道明示禁止抓取时，应停止该渠道的采集，仅保留人工录入通道。

## 3. 判定与申诉

- 每条预警必须携带：规则编号、规则名称、命中原文片段、置信提示。
- 判定不具终局性：系统输出"风险线索"，是否侵权由法务结合授权合同判断。
- 支持将任意预警标记为**误报**，误报会同步回滚线索状态并保留操作人记录。

## 4. 数据安全

- 当前为单机部署：`data/app.db` 本地存储，已加入 `.gitignore`。
- 生产部署需：数据库加密或加密磁盘、访问审计、按角色最小权限、定期备份与销毁策略。
- 快照涉及第三方平台内容，对外披露时应限于维权必要范围。

## 5. 报告与对外文件

- 系统生成的报告是**内部工作底稿**，可作为初步沟通材料，不构成法律意见。
- 对外下架通知、律师函应以公证/可信时间戳固化的原始页面为证据附件。
- 报告中不得包含未脱敏的卖家个人信息。

## 6. 知识产权

- 示例中的游戏名称仅用于说明匹配逻辑，商标与著作权归各自权利人。
- 系统不复制、不分发游戏素材；图像比对（V1.2）仅做指纹哈希，不存储原图。

## 7. 红线

1. 不协助任何账号买卖、代充、代练、找回服务；
2. 不采集、不推断未成年人信息；
3. 不将监测数据用于敲诈、骚扰、恶意竞争；
4. 不绕过技术保护措施获取非公开数据。

> 违反上述任一条款的使用行为，与本框架作者无关；部署方需自行承担合规责任。
